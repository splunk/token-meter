Hi, I'm Pratik, an AI engineer at Cisco, previously at Galileo. Every day we spend tokens like money, but the bill never tells us what we bought: which session was worth it, which model, which habit. Token Meter is a local, private meter that reads the traces your agents already write, on macOS, Linux, and Windows, across Claude, Codex, Cursor, OpenCode, Kiro, and Pi. This talk isn't a feature tour. It's the questions you already have, the five levers that change the answer, and how to run the experiment yourself. Optimizing value means more useful work per dollar, not just less spend.

How it works

From raw traces to goals

No API keys, no proxy, no extra logging. If the agent wrote it to disk, Token Meter can read it, including months of history.

Traces become tokens per request, tokens become cost at list price, and cost and tokens become metrics: output per dollar, cache hit, context load. Everything else is built on the metrics. Insights are generated from them, like trends, outliers, and live nudges, and goals are targets you set on them, like a minimum output per dollar for a model. Nothing to configure in the agent. It works retroactively on history already on disk, which is why the first open already shows months of data.

The goal of subagents is to cut cost and speed up execution by handing bounded work to cheaper models. My data says it works. Codex subagents on gpt-5.6-terra cost $0.92 a run against $3.54 on gpt-5.6-sol, and the median run finished in 262 seconds instead of 365. Across 702 child runs, subagents produced 10.2K output tokens per dollar, about 1.8 times my overall average. They're 34% of spend in the sessions that use them. From August to September, cost per run fell from $6.04 to $0.96 as runs got smaller and moved to the cheaper model. Caveat: run times compare different tasks, so they're directional, not a benchmark.

The dashboard answers the questions you planned to ask; the MCP lets your agent answer the ones you didn't. Here I asked about one long Claude session. The agent listed sessions, pulled the per-call trace, and found three things. The main conversation never compacted: 183 calls ran above 200K context and made up 62% of the cost, at about $0.11 a call against $0.035 for small contexts. Eleven calls came more than five minutes after the previous one, between 5 and 82 minutes, so the cache had expired and the whole context was written again: $6.86, 22% of the session. And 78 skills were loaded for a session that used 6. So: compact or hand off near 200K, which would have saved roughly $13, keep pauses under the 5-minute cache window or use the 1-hour cache, and load fewer skills. Everything it used was numbers and timestamps, never content. Caveat: the agent's model provider does see those numbers.

Reliable for comparing sessions, models, and trends on your own machine. Times use your local time zone.

This came up in Slack: big gaps vs. admin consoles are expected. Token Meter is usage × public list price, from local logs on one laptop. It can't see contract rates, discounts, gateway or Bedrock pricing, or seat plans, and it doesn't see web chat, CI, cloud agents, or other devices. Unknown models are excluded, never guessed, never counted as zero. Extras are priced when the logs record them: Claude web search at $10 per 1,000 searches, 1-hour cache writes at 2× input, 5-minute writes at 1.25×, and fast mode. The cache stays warm for 5 minutes by default, and each hit resets the timer; the 1-hour option costs more to write. Use it to compare; use the provider console for the invoice.
