How Token Meter reads efficiency ↗
  • ↗

    Output / covered $

    Output tokens per covered dollar. Higher is more output for the spend.

  • ≈

    Reasoning ratio

    Reasoning share of output. Stable is usually better; hard work may need more.

  • ↘

    Context load

    Input tokens per output token. Lower carries less context into each response.

  • ↗

    Cache hit ratio

    Share of cache-covered input read from the prompt cache. Higher is usually better.

No universal score. Read movement across comparable work. Coverage remains visible: missing evidence never becomes zero. Costs and selected token values can be estimates.

Open source from Signals, not verdicts.

Your traces stay on your machine.

Token Meter reads supported local stores and serves the dashboard on 127.0.0.1. It is not a hosted analytics service.

Inspect the security boundary ↗
Read-only inputs

Supported local traces and databases are read, never rewritten.

Bounded output

No prompt or response content appears in the dashboard, native companion, or bounded MCP projections.

No hosted plane

No API keys for trace analysis. No Token Meter analytics or telemetry leaves your machine.
